Personal Website Brief
Design & Content Specification for Developer Handoff
Economics Honours Student  |  Data Analysis  |  Research

1. Overview & Goals
This document outlines the full design brief and content requirements for a personal portfolio website. It is intended to be handed directly to the developer building the site. Each section describes what content should appear, how it should look and function, and any technical details relevant to implementation.

The site should achieve two things simultaneously:
	•	Project professional credibility as an economics honours student and researcher.
	•	Convey genuine personality — curiosity, interests, and life outside of academia.

2. Visual Design Direction
2.1 Aesthetic
The overall feel should be clean, dark, and polished — like a Bloomberg terminal crossed with a well-designed academic journal. Think structured and data-forward, but with room for personality. Avoid anything that looks like a generic template.

2.3 Typography
	•	Use a clean sans-serif for body and UI (e.g. Inter, DM Sans, or similar).
	•	Headings can use a slightly heavier weight of the same font, or a contrasting serif for elegance (optional).
	•	Data/chart labels: monospaced or tabular-numerals style recommended.

2.4 General Layout Principles
	•	Single-page scroll layout with anchor navigation (or multi-page with smooth transitions).
	•	Sections should feel distinct but part of the same visual system.
	•	Generous whitespace — don’t cram content.
	•	Subtle animation on scroll (fade-in / slide-up) is welcome; keep it tasteful.
	•	Fully responsive (desktop-first, but mobile must work).

3.5  Interactive Element — Three Equations / General Equilibrium Model
This is the signature interactive feature of the site. It demonstrates macroeconomic intuition in an engaging, visual way and sets this portfolio apart from a standard CV website.

What it is
An interactive macroeconomic impulse-response diagram based on the Three Equations Model (or the Four Equations General Equilibrium Model) taught in macroeconomics. The diagram shows how the economy responds to a shock under different conditions.

Suggested placement
Inside or below the Projects section — either as its own sub-section labelled “Interactive Model” or as a featured project card that expands.

Functionality
The user should be able to:
	•	Select the type of shock (e.g. demand shock, supply/inflation shock, interest rate shock).
	•	Adjust parameters / conditions using sliders or toggle buttons:
	•	Central bank hawkishness (aggressive vs. dovish response).
	•	Rational vs. adaptive expectations.
	•	Shock persistence (temporary vs. permanent).
	•	Degree of wage/price rigidity (optional, if feasible).
	•	See the impulse-response paths animate — showing how output gap, inflation, and the interest rate evolve over time.
	•	Optionally display the IS curve, PC curve (Phillips Curve), and MR rule graphically, with the equilibrium path traced through.

Technical notes:
	•	Can be built in JavaScript using a charting library (D3.js, Plotly.js, or Chart.js recommended).
	•	The underlying model equations should be coded parametrically so parameter sliders update the chart in real time.
	•	Should be self-contained and load client-side (no server-side dependencies needed).
	•	Add a small legend or tooltip explaining what each curve/variable represents — accessible to non-economists.

5. Technical Notes for Developer

	•	Framework: Developer’s choice — React, Next.js, or plain HTML/CSS/JS all acceptable. Performance matters more than stack.
	•	Interactive model (Section 3.5): Recommend D3.js or Plotly.js. Should be modular so it can be updated if model equations change.
	•	Charts / Graphs: Embed as interactive where possible (Plotly HTML). Fall back to high-res images with hover tooltips.
	•	Spotify embed: Use Spotify’s standard iframe embed widget in the personality section.
	•	Hosting: TBD by owner. Vercel, Netlify, or GitHub Pages all work.
	•	Analytics: Optional — Google Analytics or Plausible if owner wants page view data.
	•	SEO: Include meta title, description, and Open Graph tags for when the link is shared.
